# Parity checklist: Rune Stella vs Electron Stella

Every line is proven in the running Rune app (screenshot or recording on the private display,
real-display numbers for performance) before it is ticked. Source of truth is master's
`packages/desktop-ui/src` and `packages/desktop/electron`.

## Platform (engine + host)
- [ ] Windows: main shell, detached viewer windows (tear-off), companion, overlay, Show Stella panel, dialogs' parent
  - macOS: the main shell, a torn-off viewer window docking back (~/.stella/outputs/stella-rune/shell/clips/viewer-detach.mp4, ~/.stella/outputs/stella-rune/shell/sbs/detached-dark.jpg), the companion's mark and panel windows (~/.stella/outputs/stella-rune/shell/sbs/companion-expanded-*.jpg) and the full-screen overlay (~/.stella/outputs/stella-rune/shell/sbs/overlay-region-hint.jpg) open as their own windows, matching Electron's bounds (mark 1572,953; panel 1300,541 400×560). Show Stella panel and dialogs' parent are not proven here; Windows and Linux are not run.
  - Linux (omarchy, Hyprland, XWayland at scale 1.6): the main shell opens floating with the same app_id as Electron (stella-v2). The background media window ("Stella media") opens override-redirect, so it takes no focus and is not listed by window managers or taskbars. It is also absent from the accessibility tree, as Electron's hidden window is (~/.stella/outputs/stella-rune/engine/background-window-linux.txt). A second monitor is not tested (no hardware).
- [ ] Custom titlebar, window controls (Windows/Linux), traffic lights (macOS), drag regions, zoom
  - Linux: the top bar, the minimise/maximise/close controls and resizing work at fractional scale 1.6 (~/.stella/outputs/stella-rune/linux/shots/rune-home-dark.png, ~/.stella/outputs/stella-rune/linux/sbs/*.jpg). - [ ] Tray, global shortcuts, native menus, context menus (spelling, edit, selection, app groups)
  - Default app menu: Stella's main sets none on macOS, so Electron 44 shows its default menu there; Linux and Windows set null, and there is no menu bar. The host installs Electron's default template at will-finish-launching with Electron's role labels, accelerators and submenus. The engine leaves the AppKit-native roles to Rune's default bar, which now has the complete Electron set: File › Close Window, the Edit menu with Paste and Match Style, Delete, Substitutions and Speech, and Window › Minimize/Zoom/Bring All to Front (Rune e8be80b1). View holds Reload/Force Reload (the UI bundle is evaluated again), Toggle Developer Tools (disabled: no inspector), Actual Size/Zoom In/Zoom Out (Chromium's ±0.5 levels, the same zoom for every page of the origin) and Toggle Full Screen. Linux, real app: no menu bar; Zoom In ×2 lays out and draws as Electron's (heading box identical, ink within 0.6%); reload re-renders intact (~/.stella/outputs/stella-rune/shell/default-app-menu.txt, view-zoom-in-x2-electron-top-rune-bottom.png). macOS AX read of the bar is pending (steps in memory).
  - Linux: Electron has no tray on Linux (Windows only), so there is nothing to match. Global shortcuts register through the GlobalShortcuts portal and fire from Hyprland. The host computes Electron's portal ids and descriptions (Chromium's command string, hashed with Electron's Preferences uuid; reproduces the live Electron ids exactly) and the top bar's tablist holds the Chat tab as Electron's does (~/.stella/outputs/stella-rune/host/identity-linux.txt). The engine binds them under those ids and descriptions (a private D-Bus portal logged BindShortcuts; ~/.stella/outputs/stella-rune/engine/shortcut-portal-ids-linux.txt). The AT-SPI application is named "electron" in both, as Electron names it after its executable (~/.stella/outputs/stella-rune/engine/a11y-app-name-linux.txt).
